# rpi-procmon v0.3.0

Released October 21, 2026.

This release extends the central controller to local and SSH-based systemd and Docker monitoring, adds authenticated manual control, and hardens persistence and command execution.

## Highlights

- Remote targets support preferred hostnames and fallback addresses for SSH operations.
- Typed systemd and Docker checks/recovery keep remote services under one controller; remote hosts do not require procmon agents.
- Arlo monitoring supports positive log markers that supersede older failures, multiple-camera failure thresholds, and configurable recovery-attempt limits.
- Versioned `/api/v1` read routes coexist with existing endpoints. Configured check/recovery actions require an admin bearer token and remain disabled without one.
- The UI shows per-service checks, failure details, recovery timestamps, and retained events.

## Reliability and Efficiency

- Invalid runtime state/history is preserved in timestamped `.corrupt-*` files before rebuilding, preventing a corrupted JSON file from causing a startup loop.
- Persistence flushes file contents and directory updates around atomic replacement.
- Normal checks no longer rewrite unchanged event history. Live verification confirmed state advancing while the 1.5 MB history file remained unchanged.
- Command runtime is capped at five minutes, output at 8 MiB; excess output fails explicitly. SSH connection and keepalive timeouts bound connection waits.
- Cancellation terminates local command process groups and queued monitor operations without adding false service-failure counts.
- Recovery start and cooldown must be saved successfully before actions execute.
- Startup rejects unsafe durations, malformed check regexes, and invalid SSH ports. Token comparisons use constant-time comparison.

## Upgrade Notes

- Preserve the deployed configuration, environment, state, and history. This release does not require rerunning bootstrap or changing monitored-service installations.
- Browser cross-origin access defaults to `http://127.0.0.1:9645`; configure `api.cors_origin` or `PROC_API_CORS_ORIGIN` for other browser origins. Native clients and same-origin UI requests are unaffected.
- Corrupt runtime snapshots cannot retain their lost counters/cooldowns; configuration and valid companion files remain intact.
- Shell commands exceeding the new runtime/output limits now fail instead of hanging or consuming unbounded memory. Canceling a local SSH client cannot guarantee cancellation of an operation already started remotely.
- SSH fallback applies to SSH commands, not automatically to HTTP health URLs.
- Known follow-up: bootstrap merging can discard API options; this deployment uses a build/install update and leaves configuration unchanged.

## Validation

- Full Go tests, race tests, and `go vet` passed for the audited code.
- Linux ARM host tests and builds passed.
- All six deployed monitors passed: Scrypted Arlo, Homebridge, Scrypted, MA352, Snooper orchestrator, and Snooper GUI.
- Legacy/versioned read APIs and disabled-control rejection were checked live.
